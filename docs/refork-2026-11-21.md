## Corrections to the brief

1. **1.36 → 1.42 is a required hop, not optional.** The 11.0 upgrade guide
   (`.claude/skills/add-onecli/payload/docs/onecli-upgrades.md`) says a gateway
   older than 1.42 has no policy API, so `pre-upgrade-check.sh` stops. Move to
   1.42.0 first, then 1.45.0. 1.42.0 also closes a credential-injection
   bypass, so do it **now**, ahead of the refork (the 2.2.0 code supports it).
2. **The refork must apply `/add-onecli`.** Since 2.4.0 the gateway is a skill
   payload (`src/gateway-providers/`). A manual merge that does not apply it
   gives a host that refuses to start. The brief does not say this.
3. **Brief misses GHSA-j39m (critical) and GHSA-hcfx (high).** See table.
4. **Brief misses the Node update.** 24.14.0 → 24.22.3 (`sudo apt install nodejs`).
   Same major, so `better-sqlite3` needs no rebuild.
5. **Signal fix #4093 is only signal-cli 0.14.9.** This install runs the JRE
   build 0.14.7 through `SIGNAL_CLI_PATH`. `setup/install-signal-cli.sh`
   installs the *native* build to `~/.local/bin`, which `SIGNAL_CLI_PATH`
   ignores (and native cannot send images). Upgrade the JRE build to 0.14.9
   instead. Check its Java requirement first.
6. **The Anthropic secret is named `Anthropic-personal`.** 11.0 finds the model
   key of an older install only by the name `Anthropic`. Existing groups keep
   their grant after conversion, but a *new* group gets no model key. Rename
   the secret (or run `setup --step gateway-auth claude`) at switchover.
7. **Fork code needs more rework than the brief says.** 2.3.0 and 2.4.0 broke
   three fork surfaces: `claude-md-compose.ts` became `project-doc-compose.ts`
   (SOUL layering), the container runtime moved behind the driver seam and a
   typed session spec (host integrations), and central DB access became async
   (external API). The brief lists only the 11.0 template and card items, and
   those do not apply (no fork commit touches templates or card handlers).
8. **Telegram fix is likely obsolete.** Upstream removed the legacy
   `telegram-markdown-sanitize.ts`; adapter 4.41.1 renders MarkdownV2 itself.
   Drop our `\~`/`\|` hunk and verify with one test message.
9. **Webhook bind: use the LAN IP, not `0.0.0.0`.** Telegram uses polling, so
   only Home Assistant calls the webhook server. 11.0 accepts one interface IP:
   `WEBHOOK_HOST=10.50.100.12` keeps HA working and stops agent containers on
   docker0 from reaching `:3000`. Today it listens on `0.0.0.0:3000`.
10. **The OneCLI "Default Agent" is in `all` mode.** The 1.44 conversion gives
    it an explicit grant to every secret. If nothing uses it, detach them.
11. **gws mount bypasses the empty mount allowlist.** The ops side treats
    `allowedRoots: []` as "no extra mounts", but the fork mounts
    `~/.config/gws` RW into all six groups (incl. the kids' groups) in code.
    The dir holds `credentials.enc`, `.encryption_key`, `client_secret.json`
    and `token_cache.json`: any group (for example, after prompt injection from
    a web page or an email) can recover the Google refresh token.

The brief is correct on: target 11.0, worktree isolation, `pg_dump` before any
gateway change, gateway 1.45 + CLI 2.11 in the switchover, the one-way
conversion, the selective agents keep their lists, `backup.sh` drop, don't
touch the guard / allowlist, the VM snapshot as the full rollback.

   ```bash
   #!/bin/bash
   set -u
   TODAY=$(date +%Y-%m-%d)
   A=/workspace/agent
   # Brief already sent, or this gate already fired today → stay asleep.
   if [ -e "$A/morning_brief_sent_$TODAY.txt" ] || [ -e "$A/.wake_gate_fired_$TODAY" ]; then
     echo '{"wakeAgent":false}'; exit 0
   fi
   STATE=$(/app/skills/home-assistant/ha-api GET /api/states/input_datetime.jouni_woke_up 2>/dev/null \
     | node -e 'let s="";process.stdin.on("data",d=>s+=d).on("end",()=>{try{console.log(JSON.parse(s).state||"")}catch{console.log("")}})')
   case "$STATE" in
     "$TODAY"*)
       find "$A" -maxdepth 1 -name '.wake_gate_fired_*' -mtime +2 -delete 2>/dev/null
       touch "$A/.wake_gate_fired_$TODAY"
       echo "{\"wakeAgent\":true,\"data\":{\"event\":\"jouni_woke_up\",\"at\":\"$STATE\"}}" ;;
     *) echo '{"wakeAgent":false}' ;;
   esac
   ```

   The `.wake_gate_fired_<date>` file makes the gate fire at most once a day,
   even if the agent fails to write its marker.
