# Custom-branch curation — 2026-08-16

Rewrites `custom` from 18 incremental commits into 10 intent-shaped feature
commits, to cut the per-commit classification and replay work the `/refork`
flow pays on every upstream jump.

## Why

`/refork` cherry-picks **per commit** and asks of each *"would we still build
it this way today?"* Two problems with the pre-curation history:

1. **Wolfram was built twice.** `d478cee4` added it with the appid as a
   plaintext `WOLFRAM_APP_ID` env var; `7a402df5` (15 commits later) replaced
   that with an OneCLI vault secret using query-param injection. Both commits
   touch the same two **upstream-owned** files — `src/container-runner.ts` and
   `docs/SECURITY.md` — so a refork resolves conflicts against upstream twice
   for one net change. Worse, `d478cee4` in isolation looks like a valid
   integration to replay, so a refork that lands it but fumbles `7a402df5`
   silently restores the plaintext credential.
2. **17 classifications for ~10 distinct intents.** Four separate
   signal/telegram fixes, five separate docs commits.

## Invariant

This is a pure history rewrite. **The curated tree must be byte-identical to
the pre-curation `custom` tree**:

```
git diff custom.bak-<ts> curate/2026-08-16    # must be empty
```

If that diff is non-empty, the curation is wrong — no exceptions, no
"acceptable difference".

Scope note: the invariant is about the **curation**. This plan file is itself
part of the curated tree, so any later edit to it (such as appending to the
execution log below) legitimately changes `custom`'s tree afterwards. Compare
against the curate branch, or against the backup at the moment of switchover —
not against a `custom` that has moved on since.

## Method

Rebuild by content rather than by interactive rebase. Branch from `base`, then
for each target commit `git checkout custom -- <paths>` and commit. Every one
of the 29 changed paths is assigned to **exactly one** target commit, so the
union of the commits reproduces the full diff by construction.

This avoids reordering/splitting conflicts entirely. The one file needing
special handling is `.env.example`, which carries two unrelated sections; it is
written in two steps (host-integration section in C7, external-API section
appended in C8) rather than checked out wholesale.

Trade-off accepted: intermediate history no longer shows the fork's real
chronology (e.g. `docs/FORK.md` arrives complete rather than accreting). The
final tree is identical and the commits now match intent, which is what the
refork replay consumes.

## Rollback

`custom.bak-<timestamp>` is created before any branch moves and is not deleted
by this procedure. To undo after a force-push:

```
git checkout custom && git reset --hard custom.bak-<timestamp>
git push --force-with-lease origin custom
```
