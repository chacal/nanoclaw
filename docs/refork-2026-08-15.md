## Isolation & rollback model

The running service (`systemctl --user`, `/home/jihartik/nanoclaw` on `custom`)
must not be disturbed until the gated switchover. Rules:

1. **Worktree isolation** — all replay work happens in a separate worktree, not
   the live checkout:
   `git worktree add ../nanoclaw-refork -b refork/2026-08-15 upstream/main`,
   then `pnpm install --frozen-lockfile` there. Abandoning the attempt is
   `git worktree remove ../nanoclaw-refork && git branch -D refork/2026-08-15` —
   production never changes.
2. **Image tag protection** — before the first `./container/build.sh` from the
   worktree: `docker tag nanoclaw-agent:latest nanoclaw-agent:pre-refork-2026-08-15`.
   Defer the image build to the end of the replay (pre-switchover), since new
   sessions spawned by the *old* host would otherwise pick up the *new*
   `nanoclaw-agent:latest`. Per-stage gates are build/test/tsc only.
3. **Migration pre-flight** — copy `data/v2.db` into the worktree's data dir and
   boot the new host there once (channels are single-consumer, so no full
   parallel E2E — this validates startup + migrations 020/021 only).
4. **Switchover window** (gated, quiet hour): `backup.sh` + copy `data/v2.db`
   aside → stop service → branch flip in the production checkout (with
   `base.bak-*` / `custom.bak-*`) → `pnpm install --frozen-lockfile` → restart →
   verify port-3000 owner → test message per channel (cli, signal, api).
   Also in the window: update HA automation URLs (`:3002/api/webhook` →
   `:3000/webhook/api`) and delete the now-dead `EXTERNAL_API_HOST` line from
   `.env` (the old code reads it until the flip, so not before).
5. **Rollback layers** — code: reset to `*.bak-*` branches; image: retag from
   `pre-refork-2026-08-15`; DB: restore the switchover copy of `v2.db`; deps:
   `pnpm install --frozen-lockfile`; then restart. ~5 minutes worst case.
